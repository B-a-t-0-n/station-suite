# Время без ПК: проверка отдельного NTP-разрешения

18 ноября 2026 года, Макс / Android 9 / `20221212`, RV6699.
Проверен сетевой доступ к одному серверу времени. **Автоматическая установка
времени после загрузки без ПК этим тестом ещё не подтверждена.**

При предыдущих перезапусках без обычных служб ПК часы возвращались в декабрь
2022 года. Это препятствует нормальной проверке TLS-сертификатов. В постоянной
схеме нужен отдельный источник времени, доступный при закрытом остальном WAN.

## Что проверено

Выбран `194.190.168.1:123/UDP` — адрес NTP MSK-IX из
[официальной документации](https://kb.msk-ix.ru/public/ntp-server/).
На роутере временно добавлялось одно точное IPv4/порт разрешение только
для Станции перед существующим общим запретом TCP/UDP. LAN оставалась доступна.

| Проверка | Первый проход | Повтор после исправления отката |
| --- | --- | --- |
| NTP без разрешения | Ответ заблокирован | Ответ заблокирован |
| NTP с одним разрешением | Валидный ответ, 18 мс | Валидный ответ, 114 мс |
| Посторонний новый HTTPS | Заблокирован | Заблокирован |
| Установка часов пробником | Не выполнялась | Не выполнялась |
| Удаление разрешения и Apply | Подтверждено | Подтверждено |
| Полное автоматическое восстановление | Нет; профиль отключён вручную под закрытой политикой | Подтверждено |

Пробник запускался под shell UID2000, явно привязывал сокет к Wi-Fi Network,
сверял исходный IPv4 и фиксированный порт. Каждый вызов отправлял один
48-байтовый запрос. Проверялись адрес отправителя, NTP version/mode, LI,
stratum, originate timestamp, ненулевые времена и соответствие ответа
ограниченному временному окну ПК. Это SNTP без криптографической
аутентификации NTS; часы ПК были только контрольным ориентиром.

Первый откат выявил особенность прошивки: после выключения радио
`disableNetwork()` не подтвердил отключение сохранённого профиля. Wi-Fi
уже был выключен, разрешение удалено, но контроллер сохранил stop-маркер
и не запустил обычные службы ПК до исправления. Профиль затем отключён
при кратко включённом радио за сохранённым router deny. В контроллере
изменён порядок: сначала отключить профиль, затем радио. Повторная проба
полностью восстановилась автоматически; частичный успех больше не даёт
успешный код завершения.

В исправленном повторе был общий 75-секундный бюджет запросов роутера
и шестисекундный предел Java-пробника. Оба прохода использовали отдельный
85-секундный выключатель Wi-Fi на Станции и независимый процесс отката на ПК.
Если аварийный выключатель
опередит отключение профиля, полное восстановление всё ещё может потребовать
вмешательства; контроллер не должен в таком случае объявлять успех.

## Что осталось

Во время запросов активной сетью Android оставался Ethernet, а Wi-Fi выбирал
сам пробник. Поэтому ответ SNTP не доказывает, что системный NTP после
загрузки выберет Wi-Fi. ПК и кабель использовались для управления и отката.

У shell на этой прошивке есть `SET_TIME`; у Agent и Voicebridge его нет.
Предпочтительный путь — штатный Android `NetworkTimeUpdateService` с одним
разрешённым сервером. В AOSP9 `NtpTrustedTime` читает `ntp_server` при создании
singleton, поэтому одного изменения Settings для проверки недостаточно.
Нужны отдельный reboot-тест, подтверждение свежего системного NTP cache,
правильного времени до запуска ПК и фактической активной Wi-Fi Network.
Источник: [AOSP9 NtpTrustedTime](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-9.0.0_r1/core/java/android/util/NtpTrustedTime.java).

Постоянные настройки NTP не менялись. После проб Wi-Fi и профиль отключены,
временные разрешения удалены, проводной режим возвращён. Голосовые API,
ТВ-приложения и native OTA этим тестом не проверялись.
