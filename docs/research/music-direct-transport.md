# Прямой интернет для музыкальной службы

В приватном `music-config.json` поддерживается поле `transport`:

```json
"transport": "direct"
```

При `direct` каталог и загрузка аудио используют HTTPS напрямую с самой
Станции через `Proxy.NO_PROXY`. Это убирает зависимость музыки от CONNECT
на `127.0.0.1:18443` и ADB reverse. Остальные поля приватного конфига сохраняются.
Отсутствующее поле или `"transport":"tunnel"` сохраняет прежний транспорт ПК.
Другие значения, включая `null`, отклоняются до внешнего запроса. Выбор
читается при каждом новом запросе каталога/загрузке; APK перезапускать не нужно.

TLS-проверки, список разрешённых музыкальных URL/CDN, проверка redirect,
ограничения размера, кеша и времени не меняются. Автоматического перехода
между direct и tunnel при ошибке нет. Этот режим сам по себе не меняет
маршрутизацию native Quasar и не блокирует OTA.

GigaChat и Speechify отдельно используют приватный `config.json`: отсутствие
`lab_proxy_port` или значение `0` уже означает прямой HTTPS. Локальные
голосовые и config/push службы продолжают работать на loopback.

В direct-режиме LocalServices наблюдает Wi-Fi с capability INTERNET и
привязывает к нему только процесс Voicebridge. Это позволяет внешним API
работать по Wi-Fi, даже если изолированный Ethernet остаётся системной сетью
по умолчанию. Наличие сети поддерживает отдельная Wi-Fi relay-служба;
наблюдение Voicebridge само не включает Wi-Fi. При потере выбранной сети или
выключении direct привязка снимается, если она всё ещё принадлежит этому
компоненту. В `local-services-status.json` есть только флаг `directWifiBound`.
Эта привязка не является запретом выхода через другие интерфейсы.

Проверка на хосте: `python -m unittest discover -s pc/tests -p test_local_music.py -v`.
Тест проходит через настоящий loopback HTTP-сервер и HTTPS adapter с
синтетическим `HttpsURLConnection`, проверяя выбранный proxy и отказ для
неверной конфигурации без внешнего доступа.
