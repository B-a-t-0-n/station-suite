# RV6699: проверка фильтрации для Станции

17 ноября 2026 года. Проверен домашний Sercomm RV6699 с прошивкой
`v4.4.59`. Доступ к веб-панели получен стандартной учётной записью;
массовый перебор не проводился. Версия на наклейке отличается от текущей.

**Работа фильтров после применения пока не проверена. Защита Станции
от OTA на этом роутере не настроена.** В прежних пробах правила
сохранялись, но отдельная глобальная команда Apply не отправлялась.

## Уточнение после проверки штатного интерфейса

В сохранённом `template.js` функция `applyAP()` отправляет отдельную форму:

```text
todo=apply
this_file=global_nav.htm
next_file=<текущая страница>
```

Прежние скрипты выполняли сохранение через `todo=save`, но не этот шаг.
В сохранённой странице редактора оставалось сообщение
`Please do Apply to make the changes take effect.` Поэтому прежний вывод
об отсутствии рабочей фильтрации был преждевременным: таблица ниже
описывает соединения при сохранённых, но не подтверждённых как применённые
правилах. Выбранный в панели режим Custom также не доказывает его применение.

Следующая проверка должна сравнить доступность одного адреса до и после
Save → глобального Apply. Независимый откат обязан выполнить
удаление → Apply → проверку восстановления трафика. Эта проверка пока
не проведена.

## Условия проверки

До изменения настроек скачана исходная резервная копия конфигурации.
Пароли, резервная копия, адреса домашних устройств и сырые страницы
хранятся приватно, вне репозитория.

Временные правила ограничивались одним тестовым телефоном, одним внешним
IPv4-адресом и TCP-портом 80 либо 443. Станция оставалась в изолированной
проводной сети с выключенным Wi-Fi. Для удаления каждого временного
набора запускался отдельный процесс с ограниченным сроком работы.

Каждая проба создавала новый сокет, явно привязанный к Android Wi-Fi Network,
и сверяла его локальный IPv4 с адресом телефона. Поэтому прохождение
через мобильную сеть не объясняет результат. В HTTPS-пробах проверялись
цепочка сертификата и имя узла. Контрольный адрес использовался отдельно
от адреса, который требовалось заблокировать.

## Результаты

| Настройка | Проверка сохранения | Сетевой результат |
| --- | --- | --- |
| Black list: MAC, IPv4 источника и назначения, TCP 80 | Правило сохранено и включено | Запрещаемый адрес ответил HTTP 301 |
| IP Filtering, LAN: input и output в отдельных проходах | Группа сохранена | Адрес ответил HTTP 301 |
| IP Filtering, HSI: output | Группа сохранена | Адрес ответил HTTP 301 |
| Одиночный drop без дополнительного allow, LAN/HSI | Drop прочитан из сохранённой группы | HTTP и HTTPS прошли |
| Firewall Custom: LAN и HSI одновременно, input и output, TCP 443 | Custom, обе цепочки и сохранённый drop подтверждены | HTTPS прошёл с проверкой сертификата |

В интерфейсе и обработчике прошивки токен output записан как `ouput`;
при сохранении использовалось именно штатное написание. Успешные
проверки после удаления правил подтвердили доступность обоих адресов.

Пропущенный Apply — конкретный кандидат на объяснение прежнего результата;
его влияние на сеть ещё предстоит проверить. Оснований объяснять результат
неисправностью фильтра или обходом через аппаратное ускорение пока нет.
Общий white list, Firewall High и
Block Whole Internet Communication не применялись: их влияние только
на одну Станцию не установлено. Работа фильтров с IPv6 и OTA-адресами
не подтверждена.

## Восстановление и итоговое состояние

После возврата из Custom в Medium прошивка изменила один дополнительный
параметр ICMP. Для восстановления загружена исходная резервная копия
через штатную форму роутера; роутер перезапустился.

После загрузки проверено:

- Все сохранённые до тестов скрытые параметры Advanced Firewall совпали
  с исходными, включая ICMP; режим снова Medium.
- Таблицы групп IP Filtering и black/white list пусты.
- Новые HTTPS-соединения телефона через Wi-Fi к обоим контрольным адресам
  проходят с проверкой сертификата.
- Wi-Fi Станции выключен. Проводной транспорт имеет состояние `ready`,
  локальные службы — `healthy`, панель отвечает HTTP 200.

Готового правила для включения защищённого Wi-Fi Станции этот этап не дал.
Рабочая схема остаётся проводной с ограниченным транспортом ПК.
Общие границы исследования описаны в [состоянии автономного Wi-Fi](wifi-autonomy.md).
[Результаты без данных домашней сети](results/router-rv6699-2026-11-17.json)
сохраняют сетевые ответы и итоговую проверку восстановления.
