# Быстрое восстановление своей Станции

Инструкция для уже подготовленной Станции Макс: Android 9 / API 28,
arm64, проверенная сборка `20221212`, доступный ADB и доверие штатного Quasar
к своему локальному TLS. Это восстановление приложений и приватной конфигурации,
без прошивки, универсальной разблокировки или получения root.

## Выбрать исходное состояние

| Состояние | Следующий шаг |
| --- | --- |
| ADB работает, приложения или настройки потеряны | Проверить устройство и выполнить восстановление из своего локального профиля |
| После factory reset ADB недоступен | Сначала завершить официальную проводную настройку, затем повторно проверить ADB |
| Прошивка отличается, нет своего TLS/аккаунтного профиля или подходящего APK signer | Остановиться на проверке совместимости; установка APK не заменяет эти условия |

Сброс не нужен для обычного сбоя сети или приложения. В проверенном случае
после уже выполненного сброса потребовались официальная проводная настройка
со звуковым кодом, собственная приватная конфигурация и одна перезагрузка.
После этого ADB снова заработал. Сам звуковой код и аккаунтные данные в
репозиторий не входят. Этот результат не означает, что такой порядок открывает
ADB на любой заводской Станции. [Зафиксированные версии и границы проверки](../experimental/wifi-standalone/results/device-session-20221212.json).

## Подготовить личный комплект

Скачайте Station Suite из [своего проверенного выпуска](https://github.com/B-a-t-0-n/station-suite/releases)
или соберите по [BUILD.md](BUILD.md). Сохраните APK, их SHA-256, номер версии
и совместимую модель ASR. Публичный выпуск может быть старше текущих исходников:
не заменяйте версии молча и не смешивайте разные профили TLS/config.

На ПК нужны Python 3.13, Android Platform Tools (`adb`), SDK Build Tools
(`aapt2`) и `python -m pip install cryptography`. Модель ASR и её проверенные
хеши берутся из [закреплённых зависимостей](DEPENDENCIES.md); восстановитель
использует уже скачанные файлы и сам их не загружает.

Рядом, **вне клона Git**, держите свой `recovery.json` и приватные входные файлы:
Voice config, native sync, музыкальный профиль, TLS P12 и пароль к нему.
Профиль ссылается на локальные пути и SHA-256; пароли и ключи в командную строку
не передаются. Политика, baseline и TLS-пара для ПК также остаются приватными.
Этот сценарий принимает проводной профиль: в Voice config —
`lab_proxy_port: 18443`, в музыкальном конфиге — `transport: "tunnel"`
либо отсутствие этого поля. Прежний direct Wi-Fi-профиль не применяется автоматически.

Для обновления уже установленного APK должна совпадать подпись. При ошибке
подписи сохраните данные и используйте подходящий артефакт; восстановитель
не должен удалять пакет ради обхода ошибки. Собственный signer хранится отдельно
от публичного репозитория и резервной копии конфигурации.

## Bluetooth-пульт после сброса

Сброс удаляет Bluetooth-сопряжение на Станции. На проверенной прошивке системный
`REQUEST_DISCOVERABLE` открывает заглушку TvSettings, которая сразу закрывается
и не делает Станцию видимой. Agent 0.7.5 проверяет фактический режим адаптера
и сообщает об этом ограничении.

При уже восстановленном авторизованном ADB команда
[Pair-StationBluetooth.ps1](../pc/Pair-StationBluetooth.ps1) открывает видимость
ровно на 120 секунд. Передайте `-Adb`, `-Target` и `-AgentApk` с собственным
проверенным Agent 0.7.5 или совместимым выпуском; `-ExpectedSha256` позволяет
проверить его по хешу выпуска. Затем откройте настройки Bluetooth телефона,
выберите свою Станцию и подтвердите сопряжение. Доступ к контактам не требуется.
Вернитесь в пульт и выберите Станцию, если прежний выбор не сохранился.

Обёртка проверяет SHA-256 локальной и переданной копии APK, затем запускает
собственный `StationBluetoothPairing` через `app_process` от UID shell. Helper
принимает только `--open120` и `--status`; он не создаёт сопряжения сам,
не включает Bluetooth и не запускается при загрузке. Обёртка возвращается сразу,
а конечный helper-процесс через 120 секунд возвращает режим CONNECTABLE:
сам параметр duration в Bluetooth API на этой прошивке этого не делает.
Ключ `-Status` читает
режим Bluetooth без его изменения; служебный APK при необходимости копируется
в `/data/local/tmp/station-bluetooth-pairing/`. Этот способ проверен на нашей
прошивке и не гарантирует совместимость с другими сборками. После подключения
пульт использует Bluetooth HID и RFCOMM без участия ПК.

## Одна команда для подготовленного комплекта

[Restore-Station.ps1](../tools/Restore-Station.ps1) объединяет восстановление
приложений/профиля и запуск единственного PC-транспорта. По умолчанию он берёт
личные файлы из `%USERPROFILE%/.station-suite/`:
`recovery/recovery.json` и `deployment.json`. Они должны быть заранее подготовлены
для одной Станции; в публичном ZIP нет ключей или готового аккаунтного профиля.

Сначала выполните проверку:

```powershell
./tools/Restore-Station.ps1
```

Без `-Apply` проверяются PC deployment, локальные recovery-входы и совместимость
доступной по ADB Станции. Приложения не устанавливаются и службы не запускаются.
После успешной проверки полный запуск при уже работающем внешнем DHCP:

```powershell
./tools/Restore-Station.ps1 -Apply -ExternalDhcp
```

`-ExternalDhcp` явно оставляет DHCP его существующему владельцу. Когда DHCP
должен запускать сам Suite, используйте `-Apply` без этого параметра.
Для другого личного каталога задайте `-Profile` и `-Deployment` явно.
Опциональный `-PairBluetooth` после восстановления открывает через уже доступный
ADB 120-секундное окно видимости Станции при включённом Bluetooth. На телефоне всё равно
нужно выбрать Станцию и подтвердить сопряжение; pairing не берётся из профиля.
Обёртка не настраивает адаптеры, не восстанавливает закрытый ADB и не заменяет
официальную первичную настройку. Завершение `--ensure` означает найденного
или запущенного PC owner; готовность config/голоса проверяется отдельно.
Сетевые проверки и локальное `hasUpdate:false` не дают общей гарантии от OTA.

Перед установкой обёртка проверяет владельца PC-транспорта, создаёт собственный
`state/stop` и ждёт его штатного завершения до 30 секунд. Существующий стоп-маркер,
несовпадающие пины владельца или чужие служебные порты дают отказ. Процессы
не завершаются принудительно. При ошибке применения свой маркер остаётся:
сначала устраните причину, затем явно снимите блокировку для следующей попытки.
После успешного применения обёртка удаляет только свой маркер и вызывает `--ensure`.

## Если ADB уже доступен

Используйте серийный номер именно Станции из `adb devices`, отдельно от телефона.
Проверьте Android build, доступ и SELinux. Здесь и далее пути — примеры:

```powershell
$stationAdb = 'C:/Android/platform-tools/adb.exe'
$stationSerial = '<ADB_SERIAL>'
& $stationAdb devices
& $stationAdb -s $stationSerial get-state
& $stationAdb -s $stationSerial shell getprop ro.build.display.id
& $stationAdb -s $stationSerial shell id
& $stationAdb -s $stationSerial shell getenforce
```

Скопируйте [пример recovery-профиля](../config/recovery.example.json) в личную
папку и заполните его по своим файлам. Сначала выполните проверку:

```powershell
python tools/recover.py --profile D:/StationPrivate/recovery.json
```

Без `--apply` проверяются входные файлы, хеши, APK package/version и совместимость
выбранного устройства; установка и запуск не выполняются. После успешной проверки:

```powershell
python tools/recover.py --profile D:/StationPrivate/recovery.json --apply
```

При восстановлении поверх работающей установки сначала сделайте личную копию:
`--apply` обновляет указанные приложения и заменяет перечисленные Voice-файлы.
Это не единая транзакция всего стека: при ошибке часть шагов уже может быть
выполнена. Сохраните исходные APK и приватные файлы для явного отката;
не используйте сброс или удаление пакетов вместо диагностики ошибки.

Профиль задаёт Agent, Voicebridge, модель ASR и фиксированный набор приватных
файлов. Опциональные APK лаунчера и ТВ-приложений перечисляются явно. Это не
автоматическое скачивание всех приложений или копирование произвольной папки
на устройство. Оформление и Bluetooth проверяются отдельно.
При указанном APK лаунчера `launcherFiles` может восстановить явно перечисленные
файлы своего профиля и офлайн-тем с SHA-256 в каталог CleanYourTV; путь активной
темы применяется последним после проверки файлов. При наличии `launcherFiles`
после загрузки данных назначается только фиксированный Home
`com.gathin.tvhome/.MainActivity`, результат команды проверяется. Без этого
списка Home не меняется.
При `startServices: true` после загрузки компонентов запускаются Agent,
LocalServices и голосовой runtime; при восстановленном лаунчере экран возвращается
на Home. PC-транспорт эта опция `recover.py` не запускает; обёртка запускает его
отдельным `--ensure` после успешного применения профиля.
Для split-пакета ТВ-приложения нужны все совместимые части APK со своими хешами.

## Если Станция сброшена

1. Подготовьте изолированное проводное подключение по [SETUP.md](SETUP.md).
   Не включайте общий NAT/ICS вместо предусмотренного ограниченного транспорта.
2. Штатно остановите обычный PC owner и запустите ограниченный bootstrap ниже.
   Он обслуживает локальную первоначальную настройку без установленного Suite и ADB.
3. Завершите официальную проводную настройку через приложение «Дом с Алисой»
   и передачу звукового кода. Используйте свои аккаунт и приватную конфигурацию;
   публичный GitHub их не восстанавливает.
4. Остановите bootstrap через `Ctrl+C` и дождитесь его завершения.
   Перезагрузите Станцию один раз после завершения настройки. Повторно проверьте
   ADB и фактическую сборку; если доступ не появился, установка Suite пока невозможна.
5. Когда ADB доступен, выполните проверку и применение recovery-профиля из раздела выше.

[bootstrap_recovery.py](../pc/bootstrap_recovery.py) использует собственный приватный
deployment с TLS, baseline и policy, но не требует уже работающего ADB или Agent.
При внешнем DHCP, обслуживающем именно подготовленную проводную сеть:

```powershell
$bootstrapDeployment = 'D:/StationPrivate/deployment.json'
python pc/bootstrap_recovery.py --deployment $bootstrapDeployment --check --external-dhcp
python pc/bootstrap_recovery.py --deployment $bootstrapDeployment --external-dhcp
```

`--check` проверяет только локальные входные файлы; он не проверяет доступность
Станции или сетевых слушателей. `--external-dhcp` не проверяет и не запускает
DHCP executable; работающий DHCP в этой сети должен быть подготовлен отдельно.
Чтобы bootstrap запустил собственный DHCP с закреплённым SHA-256, уберите этот
параметр из обеих команд. Обычный PC owner и bootstrap не могут работать
одновременно: запуск разделяет с ним OS lock и откажет при занятых служебных портах.

Bootstrap работает до 30 минут; `--max-seconds` задаёт от 1 до 3600 секунд.
Остановить его можно также файлом `<privateDir>/state/recovery-bootstrap/stop`.
После завершения он оставляет этот маркер; для новой явной попытки удалите
только его. Маркер `state/stop` обычного PC owner — отдельный файл.

Bootstrap запускает локальные config/OAuth/registration/sync-ответы, DNS/NTP
и ответ об отсутствии обновления. Он не устанавливает приложения, не меняет
NIC, NAT, Wi-Fi или TLS-доверие Станции и не передаёт звуковой код автоматически.
Отсутствие изменений сети в его статусе не проверяет чужой NAT; изоляция
готовится отдельно. Локальный ответ `hasUpdate:false` не доказывает защиту от
всех способов OTA. CLI проверен офлайн; полная настройка после сброса именно
этим новым запуском пока не повторялась.

Повторный холодный старт с открытием TCP ADB ещё не проверен. Штатная активация
отладки и `remoteActivation:true` сами по себе не гарантируют сетевой ADB после
перезагрузки. Bootstrap не открывает этот порт самостоятельно; обычный config
с ADB lease также не сможет стать готовым без восстановленного ADB.

После наблюдавшегося сообщения об обновлении повторное чтение показало прежние
Android build/fingerprint и SHA-256 native `maind`. Это не подтверждает установку
новой ОС/native-прошивки и не исключает обновления APK до сброса. Сам factory reset
удалил Suite APK; повторная установка восстанавливает прикладной стек, а не ОС.

## Запустить транспорт и проверить результат

В восстановленной проводной схеме **ПК остаётся сетевым транспортом**:
DHCP/DNS/NTP, ограниченный CONNECT, config relay и ADB bootstrap input helper.
Речь, команды, музыка и настройки выполняются на колонке. `recover.py` не
настраивает сетевые адаптеры Windows и не заменяет подготовку PC deployment.

Для нового ПК подготовьте свой `deployment.json` и выделенный Ethernet по
[SETUP.md](SETUP.md). Сначала `python pc/start.py --deployment <PRIVATE_DEPLOYMENT> --check`,
затем обычный запуск `pc/Start-StationLab.ps1`. Не запускайте новый транспорт
поверх старого владельца тех же портов. В изолированной проводной схеме Wi-Fi
остаётся выключенным. Экспериментальный Wi-Fi-модуль не входит в быстрое
восстановление и не обеспечивает доказанную блокировку OTA.

Если DHCP уже поддерживается отдельным владельцем, используйте явный
`--external-dhcp`: профиль и его пины всё равно проверяются, но второй DHCP
не запускается и чужой DHCP-процесс не останавливается. После штатной остановки
прежних config/tunnel-процессов один вызов keepalive запускает скрытый PC owner:

```powershell
./pc/Keep-StationLab.ps1 -Deployment D:/StationPrivate/deployment.json -ExternalDhcp
python pc/start.py --deployment D:/StationPrivate/deployment.json --status --external-dhcp
```

Повторный keepalive использует проверенного владельца. OS lock и пины профиля,
entrypoint и Python предотвращают второй запуск; занятые чужие порты или живой
прежний supervisor дают отказ. `state/pc-runtime/owner.json` и `status.json`
содержат PID/статус, без секретов. `starting` ещё не означает успешной проверки
OTA/config; `ready` появляется после первой проверки. Явный файл
`state/stop` в личной папке останавливает владельца и запрещает автоматический
перезапуск; keepalive его не удаляет. Без `ExternalDhcp` остаётся обычный
режим со своим DHCP. Эти команды не меняют адаптеры Windows или существующие
задачи планировщика.

Проверьте по очереди:

1. Agent и веб-панель; локальный OTA/config отвечает ожидаемой собственной копией.
2. Bluetooth-сопряжение телефона и клавиши пульта.
3. Один голосовой вопрос и свежий поиск/запуск песни.
4. Таймер, его остановку и физический LED-дисплей колонки.
5. После отдельной перезагрузки — повторный запуск транспорта, input helper и пульта.

В Agent 0.7.5 кнопка «Подключить Bluetooth-пульт» запрашивает штатное согласие
Android и проверяет фактическую видимость. На нашей прошивке системный экран
видимости оказался заглушкой: используйте описанный выше
`Pair-StationBluetooth.ps1` или `-PairBluetooth`. На телефоне всё равно нужно
выбрать Станцию и подтвердить сопряжение; pairing не восстанавливается из
публичного пакета автоматически.

Наличие APK или открытая веб-страница сами по себе не подтверждают голос,
слышимость, физическую индикацию или автономный холодный старт.

## Лаунчер, темы и ТВ-приложения

[LAUNCHER.md](LAUNCHER.md) закрепляет форк CleanYourTV, совместимую ревизию,
масштаб Станции и офлайн-пакет тем. При полном recovery-профиле с `launcherFiles`
фиксированный Home назначается автоматически; после этого проверьте запуск,
управление и темы. Пользовательский список приложений и оформление восстанавливаются
из своей копии; не заменяйте существующий профиль вслепую.

Okko, VK Видео, Rutube, Lampa, Happ и YouTube TV устанавливаются отдельно из
источников их разработчиков с подходящей Android TV/arm64-версией. Их APK,
аккаунты и лицензии в Station Suite не включены. Не запускайте Happ одновременно
с экспериментальным Wi-Fi VpnService. Список ранее установленных приложений
не означает, что их текущие версии проверены на этой прошивке.

## Сделать копию после успешного восстановления

[tools/private_backup.py](../tools/private_backup.py) создаёт зашифрованный
allowlist-архив личных Voice/TLS/config и PC-файлов. Архив, файл пароля и
расшифрованные материалы хранятся вне Git; пароль — отдельно от архива.
Команды `backup`, `verify` и явный `restore --apply` описаны в
[SETUP.md](SETUP.md). Перед восстановлением сначала выполните `verify`.

Этот архив не сохраняет модель ASR, APK, signer, прошивку, Bluetooth pairing,
Agent private prefs и данные сторонних ТВ-приложений. Эти части личного
комплекта учитываются отдельно. `recover.py` использует заранее подготовленные
локальные файлы и не расшифровывает архив автоматически. Существующий
`private_backup.py restore` загружает Voice-файлы прямо в установленный
Voicebridge; его `private-dir` — место для PC-конфигурации, а не экспорт всех
расшифрованных файлов для recovery-профиля.
